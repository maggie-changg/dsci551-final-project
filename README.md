# 🎵 Spotify Mini-Database Engine

Custom data-processing stack for USC DSCI 551 final project.  
Everything runs in **pure Python** (no pandas / csv module helpers) and powers a Streamlit UI that feels like a SQL playground for Spotify audio features.

---

## 1. Why This Exists

- **Hands-on systems build**: Write our own CSV parser, type inference, and cleaning pipeline.
- **DataFrame from scratch**: Implement the core SQL verbs—`SELECT`, `WHERE`, `GROUP BY`, `JOIN`, `ORDER BY`.
- **UI separation**: Keep Streamlit as a thin UI surface; all logic lives in services and library modules.
- **Reproducible demo**: Ship tests + scripts so graders can rerun the full workflow end-to-end.

## 3. Data Pipeline

1. **Raw ingestion (`src/csv_parser.py`)**
   - `_split_csv_line` handles commas, quotes, and escaped double quotes.
   - `_coerce` infers `int`, `float`, or `None` (custom null vocabulary) while counting stats.
   - `read_csv` validates row lengths, skips malformed lines, and accumulates counters.
   - `write_clean_csv` emits canonical CSV with escaped commas/quotes and duplicate removal.

2. **Subset creation (`src/clean_spotify_subset.py`)**
   - Keeps just the fields needed for demos: artist, album, release date, popularity, genre taxonomy, and a few audio features.

3. **Mini DataFrame (`src/dataframe.py`)**
   - `filter`, `project`, `group_by`, `sort_by`, `join`, and `count` implemented with plain lists/dicts.
   - Aggregations supported: `avg`, `sum`, `max`, `min`, `count`.
   - `join` performs an inner join with collision-aware suffix handling.

4. **Business layer (`src/services.py`)**
   - `build_options` inspects the dataset to build dropdown values for popularity buckets, tempo ranges, month/year lists, etc.
   - `apply_pipeline` executes the complete flow: parse user filters → predicate → filter → project → group → join with `artist_meta.csv` → sort.

5. **Streamlit UI (`src/app_streamlit.py`)**
   - Imports only the public service helpers.
   - Displays each SQL-like operation in order, with tables, JSON previews, and CSV download.
   - Uses `normalize_rows_for_streamlit` to guard against non-serializable values.

## 4. Getting Started

### 4.1. Environment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt   # only if you have one; otherwise pip install streamlit
```

Dependencies are minimal: standard library + `streamlit`. No pandas allowed.

### 4.2. Data Files

1. Place the raw Kaggle CSVs inside `data/` (see `data/dataset_readme.md` for provenance).  
   The main file required is `spotify_songs.csv`. Optional: `artist_meta.csv` for join metadata.

2. Run the parser test to clean the raw data:

```bash
python tests/test_csv_parser.py
```

This accomplishes three things:
- Parses `data/spotify_songs.csv`
- Writes `data/spotify_clean.csv`
- Prints cleaning statistics + schema validation

3. Produce the lightweight subset used by the UI:

```bash
python -m src.clean_spotify_subset
```

Result: `data/spotify_subset.csv`.

## 5. Streamlit Demo

```bash
streamlit run src/app_streamlit.py
```

The app guides the reader through each stage:

1. **Load & parse** – simple counts + JSON preview.
2. **WHERE** – apply bucketed filters (popularity, danceability, energy, tempo, liveness, genre, subgenre, month, year).
3. **SELECT** – show the canonical projection (track, artist, album, release date) + CSV download.
4. **GROUP BY** – aggregate `avg(track_popularity)` and `avg(danceability)` by artist.
5. **ORDER BY** – optional ascending sort by popularity or danceability.
6. **JOIN** – inner join with `artist_meta.csv` to add origin country.

Each intermediate DataFrame is persisted so the UI can explain the full lineage.

## 7. Implementation Notes

- **Type inference**: Looks only at bare digits or floats; everything else stays as strings to preserve metadata like playlist names.
- **Null handling**: Configurable vocabulary (`"", "na", "null", ...`) converted to `None`, which makes bucket checks simpler.
- **Predicate builder** (`src/filters.py`): Consolidates all range parsing logic so Streamlit just passes strings such as `"40-60"` or `"Jan (1)"`.
- **Join safety**: `services.py` normalizes column names from `artist_meta.csv` (`Artist name`, `artist_name`, etc.) before building the join table.
- **I/O hygiene**: All helpers live below `src/`, with `tests/` modifying `sys.path` explicitly so modules remain importable in any environment.
